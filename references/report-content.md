# 内容组织与对照表

用于研究周报、方案选型、实验对照与阶段汇总。按实际材料选字段和顺序；下列结构不是固定章节模板。Word样式与分页仍以SKILL.md和word-layout.md为准。

## 从选择过程写到结果

先说明待解决的问题及已有基础，再交代选择哪些方案、为什么选择、具体如何实现，紧跟对应的验证结果和取舍。例如：为了改善某项表现，比较原方案与两种改法；实现时保持哪些条件、改变什么；得到哪些实际结果，最终保留哪条路线以及原因。

方案来源可以是上一轮结果、实际问题、论文方法或已有系统。仅讨论过的方法、项目改造、完整实现和正式采用分别标明，不把论文中的能力当作项目已经取得的成果。

## 选择对照：为什么选、怎么做

可用一张表承接研究起点和方法选择，按内容从下列字段中选取：

| 字段 | 应回答的内容 |
|---|---|
| 方案／阶段 | 比较的对象或演进阶段是什么 |
| 选择目的 | 为解决哪个具体问题而选它 |
| 实现方式 | 实际采用的结构、输入、关键设置或处理流程 |
| 优点／适用条件 | 预期收益及适合的任务或资源条件 |
| 成本／取舍 | 参数、延迟、数据需求、维护成本或覆盖差异 |
| 结果／采用情况 | 已完成什么、观察到什么、保留或调整的理由 |

常见的精简组合为“方案｜选择目的｜实现方式｜结果”，或“阶段｜实现方式｜形成的能力与选择依据”。字段较多时，拆为独立的选择表与结果表；每张表都有自己的Table编号和说明，并整体放在单页，不使用跨页续表。

## 效果对照：指标对应什么条件

结果表根据任务选取“配置｜评价指标｜完成规模｜资源成本｜采用情况”，不必每项都出现。表题、表头或相邻正文写清影响解读的条件：

- 指标名称、单位、评价类别及输出阶段；不同处理阶段分别列明。
- 数据集或样本范围、有效窗口与连续范围的区别；各类别支持数按需要给出。
- 训练与部署结构、测量设备和计时范围；不同批次或设置的必要差异。
- 哪些值来自历史复用，哪些属于本轮新增；未知或未测项目用文字标识。

成果展示按当次要求突出代表性结果、轻量化收益、完成规模或实际功能。所选指标保留其计算范围和名称，例如单类Precision不能改称整体Accuracy。图表沿用同一数据口径，不混合不同分母计算改变量。

## 多轮汇总与图表衔接

按时间阶段或方法家族展示原方案、修改目的、实现差异、实际结果与当前选择。控制组和别名可以在相应表中复用，但累计配置数、训练数和处理规模去重计算；历史模型的原结果和改动原因保留。

在读者需要比较时再放图：阶段演进用流程或趋势图，逐类结果用热力图或分组图，资源权衡用散点图，训练与部署成本用配对或分组图。表格提供可查数值，正文说明选择理由，图突出与该项选择有关的主要差异，不重复铺陈相同结论。

## 实际困难的写法

困难章节回答“本期真正被什么问题阻碍、具体影响是什么、已经如何处理、现在解决到哪一步”。从工作会话、日志、实验结果和反馈中选择与本期目标直接相关的事项，不为固定章节数量凑问题。

先写本期实际遇到的技术或执行问题，再按需要另列持续的项目级瓶颈。缺少标注、定位或系统关联等长期问题，只有已影响本期研究或验收时，才作为持续困难说明；尚未启动的功能通常放入未来计划。已有基础与尚缺环节分别写清。

每项可用连续短段落交代：

| 内容 | 应写的事实 |
|---|---|
| 问题与现象 | 在什么任务、场景或对照中，实际出现了什么 |
| 影响 | 阻碍了什么判断、训练、识别、部署或验收 |
| 已做处理 | 实际完成的定位、调整、排查或对照；未做的不补写 |
| 结果与状态 | 采取措施后的观察，以及已解决、阶段性缓解或仍待解决 |
| 后续动作 | 针对剩余问题的具体下一步，与未来计划衔接 |

以下是动作识别等实验项目中的可选写法示例，仅在材料有相应记录时使用，不固定套用示例中的结论：

- **人工标注限制跨场景判断：** 写清现有标签来源、缺少的动作区间或独立视频真值，以及因此无法完成哪项评价；人工标注计划不写成已经完成。
- **后处理过滤模型已命中的动作：** 用同一批样本的原始输出和后处理对比描述现象，说明误报约束与召回的取舍；尚未验证的原因或改法留作下一步。
- **结构改动的收益与成本不匹配：** 指出实际测过的改法、效果和部署成本变化，再写保留、调整或暂停的依据；完成实验和取得识别提升分别表述。
- **资源竞争中断实验：** 写实际中断、显存或设备变化、已采取的设备调整与恢复结果；不泛写“算力不足”，也不把已成功实验列为需要重跑。
- **多人遮挡影响身份与窗口连续性：** 写素材中已出现的场景、实际使用的主体或跟踪策略、对当前识别的影响，区分可运行、稳定跟踪与尚待实现的跨镜头关联。

分项标题直接概括具体问题。格式整理、统计口径或兼容问题确实造成阻碍时可以写，但应说明其实际后果，不用这些内容代替已经暴露的数据、算法和场景问题。

最后将已解决或阶段性解决的事项与仍需处理的事项分别归纳。“未来计划”对应未解决问题安排下一步工作和预期产出，形成从真实问题到后续行动的完整过程；不将待执行措施写成已取得成果。
